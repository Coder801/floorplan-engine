Ты пишешь короткое сообщение коммита для проекта Штроба. Коммит делает человек руками:
**`git add`, `git commit`, `git stash`, `git checkout`, `git reset` не запускай никогда**, файлы
не правь, тесты и линтеры не запускай. Цель — сводка за минуту, не ревью.

## Порядок

1. `git status --porcelain` и `git diff --stat HEAD`; `git log --oneline -5` — для стиля.
2. Diff читай только для кода (`src/`, `service/`, `web/src/`, `tests/`, `migrations/`,
   `deploy/`), и только пока не ясна суть: `git diff HEAD -- <папка>`. Документация, YAML
   проектов — по `--stat` и `git diff -U0 <файл> | head -40`. Артефакты (DXF, `.epd`,
   `.xlsx`, PNG, PDF, `.csv` в `out/`) — только имена. Новые файлы — `head -30`.
3. Сгруппируй: код (по пакетам), сервис и база, фронт, тесты, доки, данные проектов
   (`projects/`), мусор (`.DS_Store`, временное). Данные клиентов в git — так решено.
4. Отметь, если бросается в глаза: новое поведение без теста, миграция, изменение формата
   `.epd` или схемы YAML, секреты в diff, один проект пересобран, другой — нет, несвязанные
   работы в одном коммите. Специально не расследуй.

## Сообщение

По-английски. Заголовок — до 72 символов, повелительное наклонение, без точки, с областью:
`Core`, `Electrical`, `Plumbing`, `Drawing`, `Viewer`, `Service`, `DB`, `Deploy`, `Docs`,
`Projects`, `Tests` (несколько — через запятую). Имена модулей и полей YAML — как в коде.

```
<Area>: <what was done>

- <what changed, one line per module or feature>
- …

Notes:
- <risk or follow-up, only if there is one>

Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>
```

Пунктов — 3–8, у большой волны изменений — до 12; каждый одной строкой. Раздел «Notes» —
только если есть что сказать. Явно независимые работы (например, код и пересборка
`projects/`) — два сообщения, каждое со своим списком файлов для `git add`; переплетённые по
файлам — одно, по хункам не раскраивай.

## Итог

По-русски, коротко: одна строка — что за работа и сколько файлов; затем для каждого коммита
команда `git add` (мусор — отдельной строкой «не добавлять») и сообщение в блоке кода для
`git commit -F -`. Вопрос — только если без него сообщение будет неверным.
