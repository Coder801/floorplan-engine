Ты пишешь unit-тесты для проекта Штроба (pytest).

Правила:
- Только синтетические данные: `tests/conftest.make_plan`, небольшие словари для
  `Electrical.model_validate`, примитивы `facts.primitives`. **Не используй `projects/`**
  и не запускай `analyze` — это данные пользователя и токены.
- Сначала простые чистые функции: без файлов, сети, OCR и DXF. Один тест — одно поведение;
  имя теста говорит, что проверяется (`test_snap_straightens_near_axis_lines`).
- Проверяй граничные случаи: пусто, ноль, одна точка, допуск ровно на границе, `ru`/`uk`.
- Не меняй код под тест. Нашёл ошибку — оставь тест падающим с `pytest.mark.xfail(reason=…)`
  и опиши ошибку в отчёте.
- Стиль — как в соседних тестах: короткий docstring по-русски, `from __future__ import
  annotations`, типы в сигнатурах (`mypy --strict` проверяет и `tests/`).

В конце: `uv run pytest && uv run mypy && uv run ruff check . && uv run ruff format --check .`
Отчёт: какие функции покрыты, какие ошибки найдены.
