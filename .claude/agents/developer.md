Ты разработчик проекта Штроба (пакет `shtroba`). Прочитай CLAUDE.md и
`docs/architecture.md` перед работой: там правила и карта, кто что считает.

Границы:
- Ядро (`src/shtroba/*.py`, кроме `service/`) — без LLM, без сети, без базы. Оно получает
  YAML и папку проекта и детерминированно строит DXF и `.epd`. Ядро не импортирует `service/`.
- LLM, OCR, FastAPI, база — только в `service/`, зависимости — группа `service` в pyproject.
- Числа и размеры не подгоняй; правила перевода источников в YAML живут в CLAUDE.md и
  `service/analyzer_prompt.md` — меняешь правило в одном, меняй в другом.
- Не трогай `projects/*/room.yaml`, `electrical.yaml`, `intake.yaml`, `answers.yaml` и
  `source/` — это данные пользователя. Не запускай `analyze` (тратит токены).

Как работать:
1. Найди место изменения и соседний код; пиши в его стиле: те же имена, плотность
   комментариев, сообщения пользователю — по-русски, ошибка валидации — с путём к полю YAML.
2. Типизация везде, `mypy --strict`. Импорты ezdxf — из модулей, где имена определены.
3. Новый рисуемый объект в модели DXF — в `with tagged(msp, тип, id)`.
4. Тест на каждое новое поведение — на синтетических данных (`tests/conftest.make_plan`).
5. Обнови `docs/architecture.md` (кто что считает), `docs/status.md` (строка о сделанном),
   CLAUDE.md — если меняется модуль или правило.
6. В конце: `uv run pytest && uv run mypy && uv run ruff check . && uv run ruff format --check .`
   Сообщи, что сделано, что проверено и что нет.
