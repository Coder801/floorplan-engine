# Формат артефакта `.epd`, версия 1

`.epd` содержит готовый проект для постраничного показа в кабинете. Каждая страница — лист
чертежа: рамка, основная надпись, вид, таблицы, легенда. Для показа кабинету не нужны DXF,
CAD-библиотеки или шрифты: достаточно уметь рисовать пути.

Файл собирает `floorplan-engine build` вместе с `project.dxf`: `projects/<имя>/out/project.epd`.

## Контейнер

Обычный zip, сжатие deflate:

```
manifest.json
pages/01.json
pages/02.json
…
```

Все файлы внутри — JSON в UTF-8. Сборка детерминирована: из одинакового проекта получается
побайтно одинаковый файл, у записей zip фиксированная дата 1980-01-01.

## manifest.json

```json
{
  "format": "floorplan-engine/epd",
  "version": 1,
  "generator": "floorplan-engine 0.1.0",
  "project": {"name": "Квартира, вул. Вавилових, 11", "language": "uk"},
  "units": "mm",
  "pages": [
    {"index": 1, "name": "01 План", "format": "A3", "size": [420, 297], "file": "pages/01.json"},
    {"index": 2, "name": "02 Електрика", "format": "A3", "size": [420, 297], "file": "pages/02.json"}
  ]
}
```

- `stage` у страницы в манифесте (необязательный, как `stage` самой страницы) — тема листа;
  просмотр по нему не показывает вкладку `points`: ведомость точек там — в боковой панели
  листа электрики, а лист остаётся для печати.
- `format` и `version` проверяйте до чтения страниц. Файл с другой версией лучше не показывать,
  чем показать неверно.
- `pages` перечислены в порядке листов проекта. `name` совпадает с именем вкладки листа в AutoCAD.
- `format` — формат листа (`A4`…`A0`), `size` — ширина и высота листа в мм.
- `variants` (необязательный) — варианты проводки (`docs/wiring-variants.md`): `active` —
  ключ выбранного (`variant.yaml`), `default` — «как в проекте», `conduit` — что выбрано для
  гофры (`none`, `ceiling`, `walls`; `null` — «не знаю», по режиму; у старых сборок ключа нет),
  `led` — есть ли в проекте выводы LED: только тогда мастер спрашивает про блоки питания (у старых
  сборок ключа нет — не спрашивает),
  `items` — сводка без чертежей: первым — выбранный набор, за ним его соседи — тот же набор с
  одним другим ответом мастера (`variants.neighbour_variants`; сборки до 2026-11-11 — шесть
  режимов и выбранный набор, поля те же, поэтому формат не менялся). У соседа с другим монтажом
  или черновым светом ключ тот же, что у выбранного: эти опции в ключ не входят. Опции (`mode`, `route`,
  `distribution`, `path`, `conduit` — гофра: `none`, `ceiling` — на потолке, `walls` — на потолке и в стенах; у старых сборок `true`/`false` — есть ли на потолке, `plaster` — монтаж кабеля до или после штукатурки, `rough_light` — черновой свет; у старых сборок этих четырёх нет; `light_wiring` — свет: `boxes` через коробки, `chain` цепочкой без коробок, у старых сборок ключа нет — через коробки; `led_supply` — блоки питания LED: `room` у ленты, `board` в щите, у старых сборок ключа нет — у ленты; `loop_conduit` — шлейф в гофре на спуске: `separate` две гофры, `shared` одна, у старых сборок ключа нет — две), смета (`total`, `currency`, `unpriced`), кабель по трассам без
  запаса (`cable_m`), аппаратов в щите (`devices`), штробы (`chases_m`), есть ли ручные правки
  трасс (`edited`), гофра по трассам (`conduit_m`). Листы в архиве — только выбранного варианта.
  Трассы, которых в проекте нет (`electrical.yaml` `routes`), в `items` отсутствуют — просмотр
  показывает только те трассы, что есть в сводке.
- `overview` (необязательный) — общие сведения о проекте для вкладки «Общие сведения»
  (`epd/overview.py`): `object` — графы штампа (объект, здание, обозначение, стадия,
  организация) и имя проекта; `rooms` — помещения с площадью (м²) и `wet`; `area` — общая
  площадь; `ceiling` — высота потолка (мм) и `assumed` (не задана в плане); `points` — точки
  по видам, как в условных обозначениях (`key`, `text`, `count`, `unit`: шт или м у ленты);
  `panel` — схема щита, ввод, аппаратов, групп, модулей, нагрузка (Вт); `plumbing` —
  сантехника: `fixtures` (приборы по видам: `type`, `text`, `count`), `water`
  (`distribution`, `hot`: riser | boiler | null, `cold_m`, `hot_m` — м по трассам без запаса,
  `outlets`, `input_assumed`), `sewer` (`pipes` — `d` и `m`, `risers`, `bends` — отводов 45°,
  `tees` — косых тройников, `errors`), `weak` — слабых мест, `estimate` (необязательный) —
  итог сметы сантехники (`total`, `currency`, `unpriced` — позиций без цены; та же смета, что
  `out/plumbing-estimate.*`). Итог проекта в просмотре — смета электрики выбранного варианта
  (`variants`) плюс `plumbing.estimate.total`. Без электрики — без `points` и `panel`, без
  `plumbing.yaml` — без `plumbing`.

```json
"variants": {"active": "economy-floor-boxes", "default": "standard-ceiling-boxes",
  "items": [{"key": "economy-floor-boxes", "mode": "economy", "route": "floor",
             "distribution": "boxes", "total": 132056.0, "currency": "грн", "unpriced": 0,
             "cable_m": 440.2, "devices": 25, "chases_m": 61.3, "edited": false}]}
```

- `work_plan` (необязательный, с 2026-11-11) — черновик задач монтажа из смет электрики и
  сантехники (`pipeline/work_plan.py`, `docs/work-tasks.md`). Из него сервис создаёт план работ
  в базе, сам черновик не пересчитывает; просмотр его не рисует. Нет ни одной позиции в сметах
  (или прайс с ошибками и сметы электрики нет) — ключа нет. `currency` — валюта смет;
  `tasks` — задачи по номеру этапа, при равном номере сначала электрика: `key`
  (`<domain>.<этап>`), `domain` (`electrical` | `plumbing`), `order` — номер этапа в шаблоне
  раздела (`electrical/stages.yaml`, `plumbing/stages.yaml`), `title` и `result` (критерий
  приёмки, строки) — на языке проекта, `after` — ключи задач этого черновика, после которых
  (мягкая зависимость; этапа без позиций нет — его место занимают его предшественники),
  `photo` — фото при сдаче (`required`, `optional`, `none`), `lines` — позиции сметы этапа
  (`key` — ключ сметы как есть, с параметром: `work.chase.brick`, `breaker.C16`; `kind` —
  `work` | `material`; `title`, `unit`, `qty`; `price` и `sum` — `null`, если цены в прайсе
  нет), `work_total` и `material_total` — суммы строк с ценой, `unpriced` — строк без цены
  («цена уточняется»: сумма считается без них). Ключ необязательный, смысл других ключей не
  менялся — версия формата осталась 1 (`docs/development.md`).

```json
"work_plan": {"currency": "грн", "tasks": [
  {"key": "electrical.cable", "domain": "electrical", "order": 2, "title": "Прокладка кабеля",
   "after": ["electrical.chases"], "photo": "required",
   "result": ["кабель лежит по трассе и закреплён, …"],
   "lines": [{"key": "work.cable", "kind": "work", "title": "Прокладка кабеля", "unit": "м",
              "qty": 609.4, "price": 34, "sum": 20719.6}],
   "work_total": 29860.6, "material_total": 59012.2, "unpriced": 0}]}
```

### Область чертежа `view`, тема `stage`, таблицы `tables`

Необязательные ключи страницы (совместимые дополнения, версия 1):

  `panel.reserve` (необязательный) — что можно держать на резервной шине (`panel_data.reserve_data`,
  нет ключа — нет резерва или старая сборка): `limit_kw` — мощность источника (null — неизвестна),
  `limit_assumed`, `items` — группы модели: `id`, `purpose`, `power` (Вт, установленная, все линии
  группы), `steady` и `peak` — доля в расчётном пике (`loads.backup_share`, решение 2026-11-11):
  постоянная часть и самый мощный эпизодический прибор группы; пик выбора — сумма `steady` и
  наибольший `peak` (в старых сборках нет — группа считается целиком `power`),
  `kind` — для быстрого выбора (`light` — есть светильник, `heavy` — тяжёлая линия или только
  выводы приборов от 1 кВт: кондиционер, тёплый пол; иначе `sockets`; в старых сборках нет), `on`.

  `panel.master` (необязательный, нет — старая сборка) — что может отключать мастер-выключатель
  (`panel_data.master_data`): `active` — мастер-выключатель в щите есть сейчас; `items` — группы
  модели: `id`, `purpose`, `power`, `kind` (как у резерва), `on` — отключается сейчас, а пока
  мастер-выключателя нет — отключался бы по правилу; `keep` — в группе потребитель, которому
  работать без хозяев (холодильник, котёл, роутер…, `loads.KEEP_ON`).
- `view` — `[x0, y0, x1, y1]`, видовой экран чертежа на листе в мм листа (начало — левый
  верхний угол, как у примитивов). Просмотр показывает в canvas только эту область, без рамки,
  штампа и таблиц; PNG для альбома — весь лист.
- `stage` — тема листа: `plan`, `electrical`, `lighting` (план освещения), `wiring`,
  `plumbing` (вода и канализация, [plumbing.md](plumbing.md)), `panel`
  (щит в лицо), `mounting` (у сборок 2026-11-11–12: монтаж; теперь его нет — потолки и крепления в развёртках), `points` или
  `elevations` (развёртки стен, с 2026-11-12 — и потолки помещений: объект `elevation:<комната>.ceiling` (`.floor` — линии по полу), без данных стены, в `objects` — его карточка «Спальня — потолок» и карточки значений его шкал `dim:<комната>.ceiling.x1450` / `.y…` («1450 мм от стены 1.А»): значение с пунктирами и измеряемыми местами — свой объект; у них, как у щита, `view` — по объектам `elevation:<комната>.<стена>`, легенда в `view` не входит; в `tables` — «Памятка монтажника» без колонок, только `notes`, «Крепления по чертежу» и «Наименьший радиус изгиба»)
  (ведомость точок: таблица на весь лист, без `view` — просмотр показывает лист целиком). По ней в `objects` попадают только
  объекты темы (`side.STAGE_OBJECTS`): на плане — помещения, стены, размеры, проёмы; на
  электрике — точки, подписи точек, щит, кабели, LED; на проводке — линии, коробки, щит; на сантехнике — приборы (`fixture`), трубы (`pipe`), стояки (`riser`), коллекторы (`collector`), препятствия (`obstacle`); на щите — аппараты (`device`) и корпус щита; на развёртках — `elevation:<комната>.<стена>` (имя «Кухня — стена 3», длина, что за стеной; все примитивы развёртки помечены этим объектом — по ним просмотр показывает развёртки по одной). У листа щита
  нет видового экрана: `view` — рамка схемы щита (примитивов с объектом) с полем, `model` нет.
- `tables` — таблицы листа для боковой панели, текстом:

```json
"tables": [{
  "title": "Групи",
  "columns": ["Група", "Призначення", "Автомат", "Кабель", "Довжина, м", "P, кВт"],
  "align": ["center", "left", "center", "center", "center", "center"],
  "rows": [{"cells": ["QF4", "Освітлення — Кабінет*", "C10*", "3x1.5", "44,6", "0,13*"],
            "keys": ["point:a1", "wire:wire_40", "box:box_7"], "color": "#e15759"}],
  "total": ["Разом", "", "", "", "672,5", "13,25"],
  "notes": ["Висота стелі 2700 мм …"]
}]
```

У строки: `color` — кружок цвета группы у первой ячейки, `marker: "square"` — квадратный
значок без цвета (аппарат щита не на линии группы: ввод, реле, резерв, щит АКБ), `section` —
заголовок раздела. На листе «Щит» аппараты — разделами «Ввод и резерв», «Линии групп»,
«Щит АКБ» (`side._device_sections`).

- `estimate` — на странице проводки (`stage: wiring`): смета электрики для вкладки «Смета»
  просмотра — таблица того же вида, что `tables` (разделы «Материалы», «Черновые работы»,
  «Чистовые работы» — `section: true`, итог раздела —
  пустой номер, название и сумма; `total` — «Всего»); совсем без цен — ведомость объёмов
  и итогов. На печати та же смета стоит на листе проводки; файлом — `out/estimate.xlsx`
  (пишет `build`).

- `estimate` на странице сантехники (`stage: plumbing`) — смета сантехники того же вида
  (`epd/plumbing.plumbing_tables`); просмотр показывает её на вкладке «Смета» под сметой
  электрики; файлом — `out/plumbing-estimate.xlsx`.

- `legend` — на страницах электрики и освещения: условные обозначения для плашки просмотра —
  только значок и что он значит (количество — в таблице «Точки», цвета групп — в «Группах»).
  На странице проводки — наборы цветов линий (`wires_light`, `wires_sockets`, `wires_heavy`,
  `wires_low`): значок — отрезки оттенков набора, какой цвет у какой группы — в «Группах».
  `items` — примитивы значка с самого листа (мм листа, тот же вид, что в `items` страницы,
  без `o`): просмотр рисует их SVG. На листе эти примитивы остаются в `items` без объекта.

```json
"legend": [{"key": "socket", "text": "Розетка з заземленням",
            "items": [{"k": "s", "c": "#000000", "w": 0.25, "l": "E-SOCKET", "d": "M12.1 282.4L…"}]}]
```

`color` строки — цвет группы щита `#rrggbb` (кружок у первой ячейки), как у её линий.
`keys` строки — объекты чертежа (`тип:id`, как в `o`), к которым она относится: наведение на
объект подсвечивает строку, на строку — объекты. Строка с `section: true` — заголовок раздела
(смета); `hint` — пояснение к строке (в таблице «Группы» боковой панели — назначение группы, подсказка при удержании курсора на строке 2 с; `group` — группа QF строки, у такой строки глазик видимости) и к строке сметы (значок «i» у наименования; без цены — с «цена
уточняется», `estimate.HINTS`); `scope` строки работы в смете — состав работы на языке проекта: `{ includes: [что входит в цену], excludes: [что не входит — где оплачивается], result: «чем сдаётся» }` (`electrical/work_scope.py`); строка в просмотре раскрывается. Ключ необязательный: у материалов, разделов и итогов его нет. Общая подпись точек `label:a,b` относится к строкам точек `point:a`, `point:b`.

### Линии для выделения `chains`

Необязательный ключ страниц проводки (`stage: wiring`) и плана (`stage: plan`): по клику на
объект выделяется всё связанное. На плане ключ — стена, её размеры, проём или помещение; значение —
стена, её проёмы, размеры с ними и вторая сторона перегородки (`objects.plan_chains`), у проёма —
обе его стороны и размеры, у помещения — всё это по его стенам. На проводке — линия целиком. Ключ — объект (`wire:…`, `box:…` или `point:…`), значение — объекты линии:
у линии щит → коробка и у коробки — коробка и все её линии до точек; у линии коробка → точка
и у точки — эта ветка, коробка и линия щит → коробка. На свете (`stage: lighting`) — связка
выключателя целиком (`objects.light_chains`): выключатели с общими светильниками (проходные) —
одна связка; ключ — любой её объект (`point:…`, `switch_link:…`, `light_set:…`, `led_strip:…`),
значение — выключатели, их линии к светильникам, линии между светильниками и светильники,
выключатели первыми (у линии своей карточки нет, подсказка — выключателя). Новый необязательный
ключ страницы света, `FORMAT_VERSION` не меняется. Только нарисованное на странице.

```json
"chains": {"point:bath2_hood": ["wire:wire_82", "box:box_6", "wire:wire_80", "point:bath2_hood"]}
```

### Площади стен `areas`

Необязательный ключ страницы плана: по штриховке трудно попасть курсором, поэтому клик ищет стену
ещё и по площади. Ключ — стена (`wall:<комната>.<стена>`), значение — контуры в мм листа, внешние
и отверстия вместе, правило чёт-нечет (`objects.plan_areas`). Стена, накрытая соседней (верх
пилона в толстой стене), площади не имеет: её размер выделяется вместе с накрывающей (`chains`).

```json
"areas": {"wall:bath.w1": [[[393.5, 316.6], [404.2, 316.6], [404.2, 354.7], [393.5, 354.7], [393.5, 316.6]]]}
```

### Пол помещений `floors`

Необязательный ключ страницы плана (решение 2026-11-11): пол помещения или зоны открытого
помещения, который просмотр заливает при наведении; стены не подсвечиваются. Ключ — объект
подписи на листе (`room:<комната>` или `zone:<комната>.<n>` — зона по порядку в `zones`),
значение — контур в мм листа (`objects.plan_floor_rings`, `zones.plan_floors`). Новый
необязательный ключ, `FORMAT_VERSION` не меняется: старый просмотр его не читает.

```json
"floors": {"zone:hall.1": [[[512.0, 410.3], [512.0, 520.1], [560.4, 520.1], [560.4, 470.0], [512.0, 410.3]]]}
```

### Группы для соседей `groups`

Необязательный ключ страницы проводки: состав каждой группы щита — её линии, коробки
и точки. При выделении линии остальное той же группы показывается полупрозрачно (соседи),
прочая проводка — приглушённо.

```json
"groups": {"QF4": ["box:box_7", "wire:wire_40", "point:kitchen_socket_1", "…"]}
```

### Из модели в лист `model`, правка проводки `edit`

`model` — у страницы с видовым экраном: `[k, tx, ty]`, переход из мм модели в мм листа:
`x листа = k·x + tx`, `y листа = ty − k·y` (ось Y модели вверх, листа — вниз).

`edit` — необязательный ключ страницы проводки: что можно править в просмотре, мм модели.
Трассы — ортогональные ломаные от источника к цели: `path` — как считает `electrical/wiring.py`,
`lane` — как нарисовано на листе, со сдвигом в полосу пучка (те же вершины, без скруглений;
пучок может стоять в стороне от `path` на несколько мм листа). Править и искать под
курсором — по `lane`, концы пристёгивать к концам `path` отводом под 90°; коробки — место символа на стене (`at`), направление в помещение
(`inward`, на потолке — `null`), сторона квадрата `size`, отрезок стены, по которому её
можно двигать (`span`, на потолке — `null`). `manual` — применена правка из `wiring.yaml`.

```json
"edit": {
  "wires": {"wire_12": {"from": "box_3", "to": "kitchen_socket_1",
                        "path": [[2450, 3100], [2450, 2800], [1200, 2800]],
                        "lane": [[2450, 3100], [2450, 2821], [1200, 2821]], "manual": false}},
  "boxes": {"box_3": {"room": "kitchen", "group": "QF4", "label": "К3", "at": [2450, 3175],
                      "inward": [0, -1], "size": 75, "span": [[150, 3175], [3850, 3175]],
                      "manual": false}}
}
```

### 3D-сцена проводки `scene`

Необязательный ключ страницы проводки: квартира и трассы в объёме для 3D-просмотра (то же,
что `electrical/wiring.py` считает для длин, развёрнутое по высоте). Мм модели, ось Z вверх, пол — 0.

- `ceiling` — высота потолка; `assumed` — что взято допущением: `ceiling` (нет в room.yaml),
  `openings` — id проёмов с типовой высотой (дверь 2100, подоконник 900; окно без высоты в 3D — до потолка);
- `floors` — полы помещений: `rings` — контур (первое кольцо) и отверстия; `kind` — вид помещения
  (`living`, `kitchen`, `wet`, `service`, `outdoor`, как у превью) для значка в фильтре, в старых сборках его нет;
- `slab` — плита пола: внешние кольца каждой части квартиры, под стенами и в проёмах, без отверстий;
  рисуется в 3D и на мини-карте развёртки; в старых сборках её нет, и пол виден только в помещениях;
- `walls` — куски стен: `polys` — многоугольники (кольца), `z` — от и до по высоте, `normals` —
  направления в помещения (у общей перегородки — два); у всех кусков одной физической стены
  (тело, перемычка, подоконник, куски стены соседа за ней) список один и тот же. Просмотр в режиме
  «срез» держит стену с двумя нормалями (перегородку) бортиком всегда, а стену с одной —
  бортиком, когда она стоит между камерой и помещением, иначе в полный рост; угол на стыке
  перегородки с наружной стеной — кусок наружной, поэтому срезанная перегородка не оставляет
  в периметре выреза;
- `wires` — трассы: `pts` — ломаная `[x, y, z]` по осям (подъём, путь по потолку или полу,
  спуск), `color`, `group`, `route`, `from`, `to`, `room` (помещение цели — для фильтра);
  пучок — кабели в 15 мм друг от друга;
- `points`, `boxes`, `board`, `media` (слаботочный щит, необязательный) — `pos` `[x, y, z]` и
  `inward` (на потолке — `null`); у точек и коробок — `room` и `group`; `from` трассы — `board`,
  `media` или id коробки;
- `pipes`, `fixtures`, `risers` (необязательные) — сантехника (`epd/plumbing.plumbing_scene`):
  труба — `key` (`pipe:<id>`), `kind` (`cold` | `hot` | `sewer`), `d`, `color`, `room`, `pts`
  (вода — по полу на 30 мм и вверх к водорозетке, канализация — от стояка вверх по уклону к
  выпуску); подвод прибора — `key` (`fixture:<id>`), `kind`, `color`, `pos`, `inward`, `room`;
  стояк — `key` (`riser:<id>`), `pos` `[x, y]`, `r`, `z` `[от, до]`, `room`.

```json
"scene": {"ceiling": 2700, "assumed": {"ceiling": true, "openings": ["living_door_1"]},
  "walls": [{"key": "wall:living.w1", "polys": [[[[0, 0], [0, 3000], [-120, 3120], [-120, -120]]]],
             "z": [0, 2700], "normals": [[1, 0]]}],
  "wires": {"wire_1": {"pts": [[276, 2470, 1700], [276, 2470, 2700], [450, 2470, 2700]],
                       "color": "#4c78a8", "group": "QF1", "route": "ceiling",
                       "from": "board", "to": "box_1"}}}
```

### Щит в лицо `panel`

Необязательный ключ страницы «Щит» (`stage: panel`): щит данными, а не примитивами.
Просмотр рисует его своим компонентом (`web/src/widgets/PanelStage`, раскладка — `web/src/engine/panel/`) — раскладка по DIN-рейкам и вид
аппаратов по модели каталога; `items` страницы остаются для печати и PNG листа.

- `enclosure` — корпус щита из каталога (`model/panel_catalog.py`, `panel.choose_enclosure`):
  `id` (`hager.VS212PD`; подобранный по месту, когда аппараты не влезли ни в один, —
  `fitted.3x24`, без `article`), `brand`, `series`, `article`, `title`, `rows`, `per_row`
  (модулей в рейке), габарит `width`, `height`, `depth` и шаг реек `pitch` в мм, цвет `body`.
  Нет ключа (старый `.epd`) — просмотр подбирает корпус по месту сам;
- `devices` — аппараты по порядку на рейках: `id` (`QS1`, `QF4`…), `key` (как ключи строк
  таблиц, `device:QF4`), `kind`, `label` (номинал на аппарате), `title`, `group`, `feeds`
  (группы под УЗО или за контактором мастер-выключателя), `assumed`, `reserve` (на резервной шине),
  `master` (за контактором мастер-выключателя; у самого контактора — тоже), `phase` (три фазы: `L1`, `L2`,
  `L3` или `3P` — на все три; у однофазного щита ключа нет), `row` — рейка корпуса сверху,
  с 0 (`panel.panel_rows`: общие, автоматы, дифавтоматы — каждый вид со своей рейки; аппарат
  не выходит за рейку) и `model` — модель из каталога
  (`model/panel_catalog.py`): `id`, `brand`, `series`, `modules`, `width` и `height` в мм, `style`
  (как рисовать), цвета `body`, `lever`, `accent`;
- `groups` — по группе: назначение, кабель, `cable_assumed` (марки нет в модели — типовая по
  видам точек, как её кладёт проводка; с 2026-11-12, в старых `.epd` ключа нет и кабель пуст),
  мощность (Вт) и ток (А; у трёхфазной — на фазу), `assumed` (мощность типовая), цвет линий
  группы, `phase` (три фазы);
- `phases` — фаз на вводе (1 или 3), `phase_loads` — у трёхфазного щита установленная мощность
  по фазам, Вт (`{"L1": 4200, "L2": 3900, "L3": 4000}`);
- `input`, `totals` (установленная и расчётная мощность, Вт; коэффициент спроса; ток — у
  трёхфазного щита самой нагруженной фазы;
  модулей), `warnings` (слабые места: `severity`, `text`, `group`), `texts` (подписи на
  языке проекта), `external` — инвертор или вилка генератора: `to` — куда приходит его выход
  (автомат выхода инвертора `QS3` или сразу переключатель), `switch` — АВР `KM1` или
  переключатель `SA1` (с `QS3` — в его вход II), `feed` — автомат питания инвертора;
- `dc` — щит АКБ у гибридного инвертора (`panel.build_dc`): `enclosure` и `devices` (как у
  щита: `QB1` — автомат АКБ, `QP1`, `QP2` — автоматы строк панелей, `FP1`, `FP2` — УЗИП DC),
  `battery` (`voltage`, `voltage_assumed`, `capacity` кВт·ч или null, `power` кВт инвертора,
  `power_assumed`, `current` — ток разряда, А, `rating` — автомат АКБ, А, `cable` — сечение
  кабеля АКБ, мм²), `pv_strings` (строк панелей, 0–2), `texts` (`title`, `battery`, `pv`,
  `kwh` — единица ёмкости на языке проекта). Без инвертора ключа нет.
- `stickers` — наклейки аппаратов (`sheets/stickers.stickers_data`), размеры в мм: `width`,
  `height`, `pad`, `rule_y`, `band` (путь полосы под номером у цветных), `icon` (`x`, `y`, `size`,
  `stroke`), `items` — по рейкам, слева направо, щит АКБ последним: `id`, `row`, `title` (полное
  назначение), `icon` (ключ `icons`), `number` и `name` (пути SVG, кривыми: у сжатого шрифта нет
  веб-версии с кириллицей), `color` (цвет группы, у аппарата без группы — нейтральный), `on_color` (цвет номера на нём), `short_id` и `short_number` (номер линии без букв и его путь: 12 вместо QF12, аппарат без группы — как `id`); `icons` — пути использованных иконок, поле 24 × 24. В старых `.epd` ключа нет, а в сборках
  ранней версии наклейки без кривых и цветов (поле `text`) — просмотр в обоих случаях не показывает
  переключатель (`StickersStage/fresh.ts`), поэтому `FORMAT_VERSION` не менялся.

```json
"panel": {"name": "ЩР", "scheme": "proper", "input": {"label": "C40", "assumed": true},
  "devices": [{"id": "QF4", "key": "device:QF4", "kind": "breaker", "label": "C10", "group": "QF4",
               "model": {"id": "generic.breaker", "brand": "generic", "modules": 1, "width": 17.5,
                         "height": 85, "style": "breaker", "body": "#f4f4f2", "lever": "#2b2b2b"}}],
  "groups": {"QF4": {"purpose": "Освітлення — Кабінет", "cable": "3x1.5", "power": 130, "current": 0.6}}}
```

### Развёртки `elevations`

Необязательный ключ страниц «Развёртки» (`stage: elevations`): развёртки, нарисованные на
этом листе, данными (`elevations.elevation_data`). Просмотр рисует стену своим компонентом
(`web/src/widgets/ElevationStage`, холст — `web/src/engine/elevation/`) — без слоёв и подсветки общего чертежа; `items` остаются для печати
и PNG листа. Мм стены: `x` — от левого угла (вид изнутри), `y` — от пола.

- `key` (`elevation:<комната>.<стена>`, как `o` примитивов развёртки), `title`, `behind` (что
  за стеной), `length`, `height` (потолок), `height_assumed`, `top` (верх рисунка);
- `openings` — `kind`, `x0`, `x1`, `y0`, `y1`, `assumed`, у двери ещё `hinge` (`start` | `end`,
  сторона петель на развёртке; проём с другой стороны двери — тоже `door`); `chases` — `x`, `y0`, `y1`, `wide`, `low`;
- `fixings` (необязательный) — крепления кабеля на спусках по стене: `x`, `y`, `n` — сколько
  креплений на этом месте в одну линию (по кабелю спуска; нет ключа — одно); есть и без
  штроб (монтаж до штукатурки); шаг и отступ — нормы `electrical/mounting.py`;
- `cables` (необязательный, с 2026-11-12) — кабели вдоль стены: `key` (`wire:<id>`), `x`, `y0`,
  `y1` (от плоскости трассы до точки, щита или коробки), `color` (цвет группы);
- `points` — `id`, `key` (`point:<id>`, как на листах электрики и проводки), `n` (номер на
  листе электрики), `type`, `name`, `x`, `y`, `posts`, `group`, `color` (цвет группы, как
  линии проводки), `from` — откуда к точке линия проводки (коробка «К3» или щит); у точек в
  одном месте (розетки с INT, розетки с выключателем) — одна рамка: `block` — постов в ней
  всего, `slot` — сдвиг центра точки от середины рамки в постах (слаботочка — справа);
  `x` — середина рамки, без ключей точка одна;
- `boxes` — `id`, `key` (`box:<id>`), `label`, `x`, `y`, `size`, `group`, `color`, `from`;
- `back` — выводы соседа на обратной стороне: `id`, `n`, `type`, `x`, `y`, `posts`, `slot`, `block`;
- `water` (необязательный) — водорозетки и выпуски сантехники: `fixture`, `key`
  (`fixture:<id>`), `name` (прибор словами на языке проекта: «Умивальник»), `n` (номер прибора на листе «Сантехника»), `kind` (`cold` | `hot` |
  `sewer`), `x`, `y` (ось от пола), `d`, `assumed` (высота типовая);
- `board` — щит на этой стене: `key` (`board:board`), `name`, `x`, `y`, `width`, `height`;
- `face` — внутренняя грань стены на плане, мм модели (как сцена 3D): `[[x, y], [x, y]]`,
  начало — левый угол; на мини-схеме перед ней стоит человечек лицом к стене;
- `left`, `right` — соседние стены в левом и правом углу (предыдущая и следующая по обходу)
  для изометрии: `turn` (внутренний угол: 90 — видна вместе со стеной, 270 — уходит от
  зрителя, 180 — продолжение), `key`, `length`, `openings`, `chases`, `boxes`, `points`,
  `board` — в мм своей стены, как у развёртки (у стены без электрики — только проёмы).
  Ключи необязательные: без них изометрия — без соседа, мини-схема — без человечка.

```json
"elevations": [{"key": "elevation:study.w2", "title": "Кабінет — стіна 2", "length": 3070,
  "height": 3000, "points": [{"id": "study_socket_2", "key": "point:study_socket_2", "n": 21,
  "type": "socket", "name": "Розетка 4-постова", "x": 2750, "y": 850, "posts": 4,
  "group": "QF11", "color": "#8cbf5f", "from": "К20"}], "boxes": [], "chases": []}]
```

### Карточки объектов `objects`

Необязательный ключ страницы: карточки объектов, нарисованных на этом листе, для подсказок
при наведении. Ключ — тот же `тип:id`, что в `o` примитивов; страница несёт карточки только
своих объектов.

```json
"objects": {
  "wire:wire_12": {
    "title": "QF4: К3 → Розетка із заземленням, Кухня",
    "rows": [["Автомат (група)", "QF4"], ["Кабель", "3x2.5"], ["Довжина", "4,9 м: …"]]
  }
}
```

- `title` — название объекта по смыслу (у линии проводки — откуда и куда, а не `wire_n`);
- `rows` — пары «что — значение», уже на языке проекта и с единицами; показывайте как есть;
- у общей подписи нескольких точек (`label:a,b`) строки — id точек и их названия;
- `block` — у розетки, интернет- и ТВ-вывода на стене: `posts` — постов, `x` и `y` — мм от начала
  стены и от пола, `wall` — ключ развёртки стены. Закреплённая подсказка рисует по нему схему блока
  и даёт ссылку на развёртку; в старых сборках его нет.
- `brief` — у линии проводки (`wire:`) и коробки (`box:`): короткая карточка того же вида
  (`title`, `rows`) для простого вида интерфейса — откуда, куда и трасса у линии, помещение и
  высота у коробки, без автомата, кабеля и длин. Необязательный ключ, `FORMAT_VERSION` не
  меняется; в старых сборках его нет — простой вид показывает только `title`.

Карточки считает код по модели (`objects.describe_objects`), в DXF их нет. Старые файлы
без `objects` показываются как раньше — по типу и id.

### Система координат

- Единицы — **мм листа**.
- Начало координат — **левый верхний угол** листа, ось X вправо, ось Y **вниз**, как в SVG и
  Canvas.
- Значения округлены до 0,01 мм.

Чтобы получить картинку шириной `W` пикселей, умножьте координаты на `W / size[0]`.

### Примитив

| Ключ | Значение |
| --- | --- |
| `k` | `"s"` — обводка (stroke), `"f"` — заливка (fill) |
| `c` | Цвет `#rrggbb` или `#rrggbbaa` |
| `w` | Только у `s`: толщина линии в мм листа |
| `l` | Слой чертежа (`A-WALL`, `A-DIMS`, `E-SOCKET`…), чтобы прятать слои |
| `o` | Необязательно: объект проекта `тип:id`, к которому относится примитив. Нужен, чтобы подсветить объект или привязать к нему комментарий. У рамки, штампа, таблиц и легенды ключа нет |

Типы объектов в `o`:

| Тип | id | Что входит |
| --- | --- | --- |
| `room` | id комнаты | Название и площадь помещения |
| `wall` | `комната.стена`, например `living.w3` | Грани, откосы, штриховка стены |
| `dimension` | `комната.стена` | Размеры стены |
| `opening` | id проёма | Дверь с дугой, окно, подпись подоконника |
| `point` | id точки | Символ розетки, выключателя, светильника |
| `label` | id точек через запятую | Общая подпись нескольких соседних точек |
| `board` | `board`, `media` | Щит (слаботочный — `media`, слой `E-DATA`) и его подпись |
| `cable` | id кабеля | Трасса и подпись группы и сечения |
| `led_strip` | id ленты | LED-лента и её подпись |
| `device` | группа щита (`QF4`) или аппарат (`QS1`, `KV1`, `FV1`, `QD1`, `SA1`, `KM1`, `U1`, `XP1`) | Аппарат на листе «Щит» и провод его группы |

id совпадают с `id` в `room.yaml` и `electrical.yaml` проекта.
| `d` | Путь в синтаксисе SVG path |

В `d` используются только абсолютные команды:

| Команда | Аргументы | Значение |
| --- | --- | --- |
| `M` | x y | Начать новый контур |
| `L` | x y | Отрезок |
| `Q` | x1 y1 x y | Квадратичная кривая Безье |
| `C` | x1 y1 x2 y2 x y | Кубическая кривая Безье |
| `Z` | — | Замкнуть контур |

Числа разделены пробелом, перед `-` пробела может не быть. Строку `d` можно без изменений
передать в `<path d="…">`, `new Path2D(d)` или Skia.

### Правила отрисовки

- Сначала залейте фон цветом `background`, затем рисуйте `items` **по порядку**: позднее
  рисуется поверх.
- У заливки правило **nonzero**: внешние контуры идут против часовой стрелки, отверстия (буквы
  «о», «а», «р») — по часовой.
- У обводки концы и стыки круглые, без заливки.
- **Текст** приходит контурами букв в заливках `f`. Строк с текстом и шрифтов в артефакте нет.
- Типы линий (штрих, штрих-пунктир) и штриховки уже разложены на отрезки.
- Подряд идущие примитивы одного стиля и одного объекта (`c`, `w`, `l`, `o`) склеены в один `d`.
  Внутри строки может быть много команд `M`.

### Пример: страница в SVG

```js
const svg = [`<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${w} ${h}" width="${w}mm" height="${h}mm">`,
  `<rect width="${w}" height="${h}" fill="${page.background}"/>`,
  ...page.items.map(i => i.k === "f"
    ? `<path d="${i.d}" fill="${i.c}" fill-rule="nonzero"/>`
    : `<path d="${i.d}" fill="none" stroke="${i.c}" stroke-width="${i.w}" stroke-linecap="round" stroke-linejoin="round"/>`),
  `</svg>`].join("");
```

Готовый SVG можно растеризовать в JPEG любым средством: resvg, браузер, sharp.

## Эталонный рендер

`uv run floorplan-engine render-artifact projects/<имя>` строит из `out/project.epd` картинки
`out/artifact/NN-<лист>.png` (Python и matplotlib, без DXF). Картинки кабинета можно сверять
с ними.

## Изменения формата

Совместимые дополнения, например новые необязательные ключи, версию не меняют: кабинет должен
игнорировать неизвестные ключи. Любое изменение смысла существующих ключей повышает `version`.
