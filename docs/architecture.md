# Как устроена Shtroba

Карта системы: откуда берутся данные, кто что считает (код или LLM) и в какой функции.
Состояние работ и планы — в [status.md](status.md). Меняешь, где считается что-то из
таблиц ниже, — поправь и этот файл.

## Поток данных

```mermaid
flowchart LR
    src["source/<br>PDF, фото, текст"] --> facts["pdf_facts<br>(код)"]
    src --> llm["LLM-анализатор<br>(Claude)"]
    facts --> llm
    llm --> yaml["room.yaml<br>electrical.yaml<br>plumbing.yaml<br>intake.yaml"]
    human["проектировщик<br>или Claude Code"] -.-> yaml
    ans["answers.yaml<br>ответы на вопросы"] --> check
    yaml --> check["проверка и оценка<br>(код)"]
    check -->|ошибки| llm
    check -->|вопросы| ans
    check --> build["сборка<br>(код)"]
    build --> out["out/: project.dxf, project.epd,<br>report.md/json"]
```

Главное правило: **LLM только читает источники и пишет модель (YAML).** Всё, что можно
посчитать, считает код, без LLM и без API-ключей: проверку, геометрию, площади, листы,
таблицы. Одна и та же модель всегда даёт один и тот же чертёж.

Модель — единственный источник правды. DXF и `.epd` — результат сборки, из них ничего не
считается (обратный путь из DXF — будущая команда `update`).

## Пакеты и слои

Код ядра — `src/floorplan_engine/`, пакеты по смыслу, слоями сверху вниз; выше может
импортировать ниже, не наоборот (import-linter, контракты в `pyproject.toml`,
`uv run lint-imports`):

| Слой | Что | Модули |
| --- | --- | --- |
| `cli/` | команды, печать, коды выхода | — |
| `service/` | API (`api/`: app, viewer, viewer_db, work, auth), анализ (`analysis/`: analyzer, llm_analyzer, промпт, pdf_facts), разбор источников (`facts/`), база (`db/`), workflow, storage | — |
| `pipeline/` | конвейер без вывода: оценка, отчёт, DXF, `.epd`, черновик задач монтажа (`work_plan`) | — |
| `epd/` | артефакт для просмотра | artifact, objects, side, scene3d, panel_data, thumbnail, plumbing |
| `sheets/` | документ проекта, печать, PNG листов | document, layout, stages, printing, preview |
| `validation/` | проверка модели, вес вопросов, отчёт | validate, issues, plan, electrical, plumbing, answers, assess, report |
| `drawing/` | рисование DXF | layers, ids, symbols, fields, titleblock, tables, schedules, labels, plan, electrical, wiring, mounting, panel, elevations, lighting, plumbing |
| `plumbing/` | сантехника: сеть, слабые места, строки таблиц, смета ([plumbing.md](plumbing.md)); выше электрики — берёт её трассировку, цены, развёртки | network, rows, estimate, stages |
| `electrical/` | расчёты электрики и щита | anchors, wiring, wiring_model, boxes, chases, routing, lines, groups, point_numbers, estimate, work_scope, stages, mounting, loads, panel, panel_questions, panel_text, elevations |
| `model/` | данные проекта | schema, plumbing, intake, texts, geometry, scale, panel_catalog |

Ниже в таблицах функции записаны как `модуль.функция` (`wiring.box_wiring`); у одноимённых
модулей разных пакетов — с пакетом (`drawing.wiring.lay_out`, `electrical.wiring`). Ядро
не импортирует `service/`; `model/`, `validation/`, `electrical/` не импортируют ezdxf.
Исключений из слоёв нет: общее для расчёта и рисования лежит ниже — геометрия помещений
(`geometry.room_geometries`), масштаб листа (`scale.sheet`), якоря точек и размеры символов
(`anchors.point_anchor`, `anchors.SYMBOL_DEPTH`), ключ и цвет группы (`groups.group_key`, `colors.group_colors`);
таблицы для листа собирает рисование (`drawing/schedules.py`) из строк расчётов.

## Модель проекта (YAML)

| Файл | Что в нём | Схема |
| --- | --- | --- |
| `room.yaml` | Помещения: стены по часовой стрелке (`id`, длина, угол `turn`, толщина, несущая), проёмы (дверь, окно, проём; `offset`, ширина, петли, подоконник), язык надписей, данные штампа | `schema.Plan` |
| `studio.yaml` (над папками проектов) | Профиль студии: организация, стадия, подписи — подставляются в пустые графы `sheet` | `schema.Studio`, `answers.apply_studio` |
| `electrical.yaml` | Точки (тип, стена + `offset` + высота или потолок `[x, y]`, постов, клавиш, группа), щит, кабели (откуда, куда по порядку, группа, марка, `route`), LED-ленты | `schema.Electrical` |
| `plumbing.yaml` | Вода и канализация: стояки (`at` от origin), узел ввода, приборы у стены (тип, `offset`, высоты подводов), препятствия, разводка (`collector` / `tee`) | `plumbing.Plumbing` ([plumbing.md](plumbing.md)) |
| `intake.yaml` | Какие источники разобраны, что известно об этапах, вопросы (`target` — поле модели, `assumption` — что сейчас стоит) | `intake.Intake` |
| `answers.yaml` | Ответы: число, выбор, «принять допущение», текст; ответ заказчика — всегда текст: ждёт студию, `resolved` (учтено) или `returned` (возвращён с комментарием); `log` — кто и когда ответил и разобрал в просмотре | `intake.Answers` |

Все объекты ссылаются друг на друга по `id` (точка → стена, кабель → точки, вопрос →
поле), а не по номеру. Поэтому ссылки не ломаются, когда что-то добавили или убрали.

## Кто что делает

### Чтение источников

| Что | Кто | Где |
| --- | --- | --- |
| Масштаб листа векторного PDF (мм на pt) | код | `facts.analysis._scale`: медиана подпись ÷ длина по согласным размерам |
| Размеры: подпись, длина линии по масштабу, концы, «≠» при расхождении | код | `facts.analysis.page_facts`, `_dimension_lines`, `_centered`, `_moved_out` |
| Цепочки размеров, суммы, сверка с общим размером | код | `facts.analysis._chains`, `_overall` |
| Выбор адаптера: картинка — растр; PDF — постранично (есть векторный текст — вектор, нет — рендер и растр) | код | `facts.source.read_source` |
| Растр: OCR чисел и надписей по плиткам (+ проход по повёрнутому листу для вертикальных подписей), отрезки по Хафу с выпрямлением и склейкой; размер внутри слитой линии — между засечками у подписи | код | `facts.raster.image_sheet`, `ocr_words`, `line_segments`; `facts.analysis._centered_span` |
| Порог «не удалось»: есть ли страница с масштабом, от 4 размеров и уверенностью от 0,8; текст годится всегда; иначе `rejected` без вызова модели | код | `facts.gate.check_sources`, `workflow.Workflow._gate` |
| Точность растра против вектора (верно / ошибка OCR / пропуск / лишние, масштаб) | код | `facts.bench.compare` (команда `facts-bench`) |
| Выжимка в JSON для базы (версия алгоритма, уверенность) | код | `facts.analysis.to_dict`, `from_dict` |
| Примитивы страницы: надписи и отрезки с уверенностью (вектор — 1), общий вход разбора для любого формата | код | `facts.primitives.Sheet`; адаптер векторного PDF — `facts.vector.read_pdf` |
| Надписи с координатами, высоты «Н=…», многострочные заметки | код | `facts.vector._labels` (из символов PDF), `facts.analysis._blocks` |
| Что за комната, какой символ, к какой стене относится размер | LLM | `service/analysis/llm_analyzer.py`, правила — `service/analysis/analyzer_prompt.md` |
| Запись модели, допущения, вопросы | LLM (или человек) | то же |
| Сканы и фото (вектора нет) | LLM по картинке | то же |

Анализатор: Opus 5.5, effort `medium`, один вызов. Ошибки проверки возвращаются модели,
не больше двух исправлений. Бэкенды: `claude-code` (подписка, `claude -p`) и `api` (ключ).
Расход каждого вызова — в `usage.jsonl`. Опция `--electrical-model` — электрика вторым
шагом другой моделью.
