# Штроба (floorplan-engine)

Чертежи DXF для AutoCAD и BricsCAD — план помещения и электрика — по описанию в YAML.
YAML по фото с размерами или по текстовому описанию составляет Claude Code в этом
репозитории (команды `/plan`, `/electrical`). Код только проверяет описание
и детерминированно строит DXF и артефакт `.epd` для просмотра: никаких LLM и API-ключей.

- Один файл `out/project.dxf` (R2018, мм, `$INSUNITS = 4`):
  - **модель 1:1** — все этапы на своих слоях (`A-*` план, `E-*` электрика);
  - **план освещения** — лист сразу за электрикой: свет и выключатели, что чем включается
    (поле `controls` выключателя или допущение «*» по группе и подписи), таблица «Выключатели»;
  - **развёртки стен** — листы «Розгортки» в конце комплекта: каждая стена с электрикой
    изнутри помещения — проёмы, точки (номера — как на листе электрики), щит, коробки, штробы;
    отступы от левого угла и высоты от пола;
  - **лист на каждый этап** (вкладки «01 План», «02 Електрика», «03 Проводка»): рамка и
    основная надпись в мм листа, видовой экран, в котором заморожены слои чужих этапов.
    Лист — четыре секции с крестом в углу штампа: план (по центру, ≈ 94 % секции) | таблицы
    (прижаты вправо) / легенда | штамп.
    Формат и масштаб — общие для комплекта; бумага — `DWG To PDF.pc3`.
- PNG листов при сборке не пишутся: листы смотрят в браузере (`view`, canvas из `out/project.epd`),
  PNG листа для альбома или техпаспорта страница делает сама (не больше A3, 150 dpi), печатают DXF.
  Для проверки — `render-artifact` → `out/artifact/NN-<лист>.png`; `build --png` и `preview` —
  PNG из DXF движком ezdxf (отладка).
- Артефакт для кабинета — `out/project.epd`: zip со страницами-листами, готовыми к отрисовке
  (контуры в мм листа, текст — контурами букв). Формат: [docs/epd-format.md](docs/epd-format.md).
- Кириллица — текстовый стиль `PLEX_LIGHT` со шрифтом IBM Plex Sans Light (лежит в пакете).

**Что можно править в AutoCAD.**
- Основная надпись — блок `STAMP_F3` с атрибутами (графы 1–9, подписи): EATTEDIT.
- Площади в подписях помещений и в «Експлікації приміщень» — **поля AutoCAD**. Они считаются
  от контуров помещений на непечатаемом слое `A-AREA`. Растянули стену вместе с контуром
  (STRETCH рамкой), выполнили REGEN — площади и итог пересчитались.
- Удалишь или перерисуешь контур на `A-AREA` — поле покажет `####`.
- У символов точек электрики есть невидимые атрибуты `ID`, `H` (высота) и `GROUP`, их правят
  через EATTEDIT. У каждого объекта модели есть метка XDATA `FLOORPLAN_ENGINE` с типом и id из YAML,
  например `wall` / `living.w3`. Метки нужны, чтобы потом переносить правки из AutoCAD
  обратно в проект. Не удаляйте их.

## Установка

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run floorplan-engine --help
```

## Команды

```bash
uv run floorplan-engine check   projects/kv42                          # только валидация
uv run floorplan-engine build   projects/kv42                          # out/project.dxf + project.epd
uv run floorplan-engine build   projects/kv42 --png                    # ещё PNG листов из DXF (sheets/)
uv run floorplan-engine preview projects/kv42                          # PNG листов из готового DXF
uv run floorplan-engine render-artifact projects/kv42                  # PNG листов из out/project.epd (проверка)
uv run floorplan-engine serve --data data/projects                     # API сервиса, документация на /docs
uv run floorplan-engine dev                                            # просмотр собранных projects/: API + страница, http://127.0.0.1:5173
uv run floorplan-engine view                                           # только API просмотра (порт 8000)
uv run floorplan-engine estimate projects/kv42                         # смета электрики таблицей
uv run floorplan-engine print projects/kv42 --paper A3                  # PDF-альбом на A3
uv run floorplan-engine analyze projects/kv42                          # LLM-анализ source/ → YAML
uv run floorplan-engine pdf-facts projects/kv42/source/plan.pdf        # выжимка из PDF без LLM
uv run floorplan-engine symbols symbols/                               # блоки УГО в отдельные DXF
```

`build` сначала проверяет проект. При ошибках не создаётся ни одного файла, код выхода 1.
После записи DXF перечитывается и проходит аудит ezdxf. Лист электрики появляется, если
в проекте есть `electrical.yaml`.

## Печать: PDF-альбом

`floorplan-engine print projects/<имя>` — все листы собранного `out/project.dxf` одним PDF
`out/album.pdf`: страница — ровно формат листа, линии — своей толщины, текст — кривыми; печать
«в размер» (100 %) даёт масштаб чертежа. `--paper A3` (A4…A0) — комплект под заданный формат:
листы раскладываются заново, масштаб подбирается по плану (обычно мельче, 1:75 или 1:100),
таблицы, что не влезли, — на листы «… (продолжение)» со штампом «Таблицы к листу N»; длинные
таблицы (смета, точки) делятся по строкам на колонки. Результат — `out/print-A3.dxf` и
`out/album-A3.pdf`; `out/project.dxf` не меняется.

Перед записью команда проверяет каждый лист и печатает предупреждения: текст мельче 1,8 мм
(ГОСТ 2.304), чертёж за рамкой, пустой лист (содержимое не влезло — например, таблица
аппаратов щита шире A4). Формат A4 для квартиры обычно мал: план не помещается даже в 1:100.

## Смета электрики

`floorplan-engine estimate projects/<имя>` — смета без чертежа: `out/estimate.md` (разделы
«Материалы» и «Работы», итоги, допущения), `out/estimate.csv` (UTF-8 с BOM, «;») и
`out/estimate.xlsx` — Excel с формулами: сумма строки «кол. × цена», итоги разделов и «Всего»
пересчитываются, если поменять цену или количество (эти ячейки подсвечены).
Объёмы считает код по модели — тем же расчётом, что лист проводки: кабель по маркам с запасом
15 %, подрозетники и механизмы по постам, рамки, распаечные коробки, соединения под опрессовку
(L, N, PE в коробке и по одному на клавишу выключателя; во влажных помещениях `wet: true` —
коробки IP44), крепления кабеля (шаг 400 мм), штробы узкие (1–2 кабеля) и широкие (3–4),
силовые и слаботочка — раздельно, сверление проходов через стены над дверями (трассы по
потолку; по полу, `route: floor`, — без сверления), автомат на группу, сборка щита по модулям,
маркировка концов линий и замер изоляции на группу. Выпуск кабеля в щите — до пола. Линии
сечением от 4 мм², выводы к технике и слаботочка идут от щита без коробок (`direct`).

Смета этапа стоит на его CAD-листе: смета электрики — на листе проводки, под таблицей кабелей
(`build`). Есть `prices.yaml` — с ценами и итогами; нет — ведомость объёмов без цен. Таблица
одна и та же в DXF, в просмотре и в PNG листа.

Цены — в `prices.yaml` в папке проекта; нет его — общий прайс студии `projects/prices.yaml`
(рядом со `studio.yaml`), один на все проекты. Цена за единицу по ключу позиции (ключи — `LINES`
в `estimate.py`, кабель — `cable.<марка>`), своё наименование — `{ price, name }`, состав щита
сверх автоматов — `board_kit`. Позиция без цены остаётся в смете с пометкой «нет цены» и в итог
не входит; неизвестный ключ — ошибка с путём `items.<ключ>`. LED-подсветка в смету пока не
входит: лент и блоков питания в модели нет.

```yaml
currency: грн
date: "2026-10"
items:
  cable.3x1.5: { price: 45, name: "Кабель ВВГнг 3×1,5" }
  socket_box: 20
  work.chase: 200
board_kit:
  - { name: "Реле напряжения", price: 1500, modules: 2 }
```

## Сервис

`floorplan-engine serve` запускает API (FastAPI). Через него проходит весь цикл: загрузка
источников → анализ → вопросы → ответы → сборка `project.dxf` и `project.epd`. Описание API,
состояния проекта и цикл работы — в [docs/service-api.md](docs/service-api.md).

Собранные проекты (`projects/<имя>/` после `build`) можно смотреть в браузере. Одна
команда — `uv run floorplan-engine dev` → `http://127.0.0.1:5173`: она запускает API (`view`,
порт 8000) и страницу (`web/`, `npm run dev`). Листы, этапы, вопросы с ответами из
`answers.yaml`, замечания проверки, файлы `out/`, источники и YAML модели. Если YAML правили
после сборки, страница предупреждает, что листы устарели.

На листе проводки трассы можно поправить руками: «Править трассы» → тянуть участок линии
(соседние участки удлиняются или укорачиваются, углы остаются прямыми), ⌘/Ctrl+клик —
выделить несколько участков, коробку на стене — вдоль стены, на потолке — свободно.
Потребители и щит не двигаются. «Сохранить» пишет `wiring.yaml` в папку проекта и
пересобирает проект: длины кабеля, таблицы, смета и DXF — по новым трассам. «Автотрасса»
возвращает выделенное к тому, как строит программа.

Кнопка «3D» на листе проводки показывает проводку в объёме: трассы по потолку (по полу — в
стяжке), спуски к розеткам и выключателям, коробки и щит. По умолчанию — изометрия; вращение —
левой кнопкой, сдвиг — правой. Стены: «Срез» (стены между камерой и помещением — низким
бортиком), «Прозрачные», «Без стен»; часть линии, закрытая стеной, видна бледно. Клик
выделяет линию, двойной клик — наводит на неё.

Фронт просмотра — самостоятельный проект `web/` (React + TypeScript, сборка Vite): своя
сборка в `web/dist`, команды, выкладка и устройство — в [web/README.md](web/README.md). Бэк —
только API; в Python-пакете фронта нет.

**Выкладка просмотра (Railway).** `Dockerfile` в корне собирает один контейнер: Caddy
(`deploy/Caddyfile`) слушает `$PORT`, отдаёт `web/dist` и проксирует `/api` на `view`.
Проекты лежат в `PROJECTS_DIR` (по умолчанию `/data/projects`; на Railway к этому пути
подключается Volume). Источник правды — git: при каждом старте `deploy/start.sh` заменяет
проекты на volume копией из образа, сохраняя с сервера только `wiring.yaml` (правки трасс в
просмотре), и пересобирает их. Проекты, которых нет в образе, не трогаются. Правки трасс на
сервере в git не попадают, и `wiring.yaml` с сервера важнее, чем из git: чтобы сервер взял
версию из git, удалите файл на volume.
Авторизации нет: кто знает адрес, видит проекты и может править трассы.

```bash
docker build -t floorplan-view . && docker run -p 8080:8080 floorplan-view   # http://localhost:8080
```

**Анализатор** (`--analyzer` у `serve` и `analyze`):

| Значение | Как работает |
| --- | --- |
| `manual` | Модель загружает оператор (`PUT /projects/{id}/model/{файл}`) |
| `claude-code` | `claude -p` по подписке Claude, для разработки и своих проектов. Нужен установленный Claude Code с выполненным входом |
| `api` | Anthropic API, ключ берётся из `ANTHROPIC_API_KEY`. Для продукта: по [условиям Anthropic](https://code.claude.com/docs/en/agent-sdk/overview) сторонний продукт не может работать через вход по подписке |

Модель по умолчанию — `claude-opus-5-5`, effort — `medium` (`--model`, `--effort`).
С `--electrical-model` (например, `claude-sonnet-5-5`) анализ идёт в два шага: план, затем
электрика по готовому плану этой моделью. На vavilovykh-11 это не дешевле одного шага.

Анализатор читает `source/` и пишет `intake.yaml` и YAML этапов. К каждому векторному PDF
он прикладывает выжимку, которую считает код без LLM (`pdf-facts`): масштаб листа, размеры
(подпись и длина размерной линии по масштабу, расхождения), цепочки с суммами и надписи с
координатами в мм. Модели остаются смысл и решения, а арифметику и привязки делает код. Если проверка ядра находит
ошибки, анализатор возвращает их модели, не больше двух исправлений. Каждый вызов LLM
записывается в `usage.jsonl` проекта: токены, стоимость, длительность. В сервисе сумма видна
в `llm_calls` и `llm_cost_usd` проекта. Для `claude-code` стоимость — оценка Claude Code,
при подписке это не реальный счёт.

## Проект

Один проект — одна папка:

```
projects/kv42/
  intake.yaml        # что разобрано, этапы, вопросы
  answers.yaml       # ответы на вопросы
  room.yaml          # план
  electrical.yaml    # электрика (необязателен)
  wiring.yaml        # ручные правки проводки из просмотра (необязателен)
  source/            # исходные фото и заметки
  out/               # project.dxf, project.epd, report.md, report.json; artifact/NN-<лист>.png — render-artifact
```


## Формат room.yaml

```yaml
units: mm
name: "Квартира 42 м²"
default_wall_thickness: 120
rooms:
  - id: kitchen
    name: "Кухня"
    origin: [0, 0]                 # левый нижний ВНУТРЕННИЙ угол
    walls:                         # по часовой стрелке по внутреннему контуру, первая — вверх
      - { id: w1, length: 3200 }                                 # левая
      - { id: w2, length: 4100, turn: 90 }                       # верхняя
      - { id: w3, length: 3200 }                                 # правая
      - { id: w4, length: 4100, thickness: 200, bearing: true }  # нижняя, несущая
    openings:
      - { id: kitchen_door_1,   wall: w1, type: door,   offset: 300, width: 800 }
      - { id: kitchen_window_1, wall: w3, type: window, offset: 900, width: 1400, sill: 850 }
source: photo                      # photo | text | measured
```

### Лист, основная надпись, язык

Каждый лист оформлен по ДСТУ Б А.2.4-4:2009: рамка (поле для підшивки 20 мм слева,
5 мм с остальных сторон), основная надпись 185 × 55 мм по форме 3 (блок `STAMP_F3` с атрибутами),
дополнительные графы 20–22 на поле для підшивки, «Копіював» и «Формат» под рамкой. Форматы — по
ГОСТ 2.301, на который ссылается ДСТУ. Формат A4…A0 один на весь комплект — наименьший, на
котором все листы раскладываются в 1:50 (или `sheet.format`). Масштаб тоже общий — самый
подходящий из 1:20, 1:25, 1:30, 1:40, 1:50, 1:75, 1:100 — план занимает около 94 % своей секции;
текст и символы на бумаге при этом одного размера. План — лист 1, электрика — лист 2,
проводка — лист 3. Блок `sheet` необязателен:

```yaml
language: uk                       # ru | uk — язык надписей на чертеже (по умолчанию ru)
sheet:
  code: "VAV11-АР"                 # графа 1 — обозначение
  object: "Квартира, вул. Вавилових, 11"  # графа 2; по умолчанию name
  building: "Перепланування квартири"     # графа 3
  stage: "Р"                       # графа 6
  organization: ""                 # графа 9
  format: auto                     # auto | A4 | A3 | A2 | A1 | A0
  signatures:                      # до 8 строк; date по умолчанию — месяц сборки (ММ.ГГ)
    - { role: "Розроб.", name: "Іваненко" }
```

**Профиль студии** — `studio.yaml` в папке над проектами (`projects/studio.yaml`; у сервиса —
в папке `--data`). Его графы подставляются в `sheet` каждого проекта, где они не заполнены;
заполненное в `room.yaml` важнее. Обозначение, объект и будинок — свои у каждого проекта,
в профиле их нет.

```yaml
organization: "ТОВ «Дизайн-студія»"  # графа 9
stage: "Р"                            # графа 6
signatures:
  - { role: "Розробив", name: "Іваненко" }
  - { role: "Перевірив", name: "Петренко" }
  - { role: "ГІП", name: "Сидоренко" }
  - { role: "Н. контр.", name: "Коваленко" }
```

Текст в графах не выходит за линии: ширина меряется по метрикам шрифта, высота уменьшается до
2,5 мм (ряд ГОСТ 2.304), дальше текст сжимается по ширине; в графах 2, 3, 4 и 9 длинное
значение переносится на вторую строку (атрибуты `OBJECT` и `OBJECT_2` и т. д.).

Шрифт надписей — IBM Plex Sans Light (OFL), лежит в `src/floorplan_engine/fonts/`. Превью берёт
его оттуда; чтобы DXF выглядел так же в AutoCAD/BricsCAD, установите шрифт в систему.

### Обход стен

```
              w2 →
   ┌──────────────────────┐
 ↑ │                      │ w3
 w1│       помещение      │  ↓
   │                      │
   └──────────────────────┘
 origin       ← w4
```

- Стены идут **по часовой стрелке по внутреннему контуру** от `origin`. Первая по умолчанию
  направлена вверх (`start_angle: 90`).
- `turn` — **внутренний угол** между стеной и следующей:
  - `90` — обычный угол (по умолчанию);
  - `270` — входящий угол Г-образной комнаты;
  - `180` — стена продолжается прямо.

  Сумма углов должна быть (n − 2) · 180.
- Толщина откладывается **наружу** от внутреннего контура.
- `offset` проёма — от **начала** стены (по направлению обхода) до края проёма.
- У каждой стены `id`, уникальный в комнате (`w1, w2…` по обходу). Всё, что стоит на стене,
  ссылается на неё по `id`. Если стену добавили или убрали, `id` остальных не меняются, и
  привязки проёмов и электрики не сдвигаются.

Г-образная комната 4000 × 3000 без угла 1500 × 1000:

```yaml
walls:
  - { id: w1, length: 3000 }             # вверх
  - { id: w2, length: 2500 }             # вправо
  - { id: w3, length: 1000, turn: 270 }  # вниз, затем входящий угол
  - { id: w4, length: 1500 }             # вправо
  - { id: w5, length: 2000 }             # вниз
  - { id: w6, length: 4000 }             # влево
```

### Поля

| Поле | Обяз. | Описание |
| --- | --- | --- |
| `name` | да | Название чертежа |
| `default_wall_thickness` | да | Толщина стен по умолчанию, мм |
| `source` | да | `photo` / `text` / `measured` |
| `rooms[].id` | да | Латиница, цифры, `_`, `-`; на него ссылается электрика |
| `rooms[].name` | да | Подпись на плане |
| `rooms[].origin` | | `[x, y]`, по умолчанию `[0, 0]` |
| `rooms[].start_angle` | | Направление первой стены, градусы; по умолчанию 90 (вверх) |
| `walls[].id` | да | Уникален в комнате: `w1, w2…` |
| `walls[].length` | да | Длина по внутренней грани, мм |
| `walls[].turn` | | Внутренний угол к следующей стене; по умолчанию 90 |
| `walls[].thickness` | | Толщина, мм |
| `walls[].bearing` | | `true` — несущая, штрихуется |
| `openings[].id` | да | Уникален в проекте: `kitchen_door_1` |
| `openings[].wall` | да | `id` стены |
| `openings[].type` | да | `door` / `window` / `opening` (проём без заполнения) |
| `openings[].offset` | да | От начала стены до края проёма |
| `openings[].width` | да | Ширина проёма |
| `openings[].sill` | | Высота подоконника (только `window`) |
| `openings[].height` | | Высота проёма |
| `openings[].hinge` | | Петли двери: `start` (по умолчанию) / `end` |
| `openings[].swing` | | Открывание: `in` (по умолчанию) / `out` |

**Соседние комнаты.** Общая перегородка описывается в обеих комнатах с одинаковой толщиной.
Дверь ставится в одной комнате (`door`), в другой на том же месте — `opening`. У соседа стена
обходится в обратную сторону, поэтому `offset_соседа = длина − offset − width`.

## Формат electrical.yaml

```yaml
units: mm
points:
  - { id: kitchen_socket_1, room: kitchen, wall: w2, offset: 500,  type: socket, height: 300, count: 2, group: QF1 }
  - { id: kitchen_socket_2, room: kitchen, wall: w2, offset: 1800, type: socket, height: 1100, group: QF1, note: "рабочая зона" }
  - { id: kitchen_switch_1, room: kitchen, wall: w1, offset: 1200, type: switch, height: 900, group: QF2 }
  - { id: kitchen_light_1, room: kitchen, ceiling: [1600, 2050], type: light, group: QF2 }
board: { room: hall, wall: w1, offset: 200, height: 1700 }
cables:
  - { id: cable_1, from: board, to: [kitchen_socket_1, kitchen_socket_2], group: QF1, cable: "3x2.5", route: wall }
  - { id: cable_2, from: board, to: [kitchen_switch_1, kitchen_light_1], group: QF2, cable: "3x1.5", route: ceiling }
```

| Поле | Описание |
| --- | --- |
| `points[].type` | `socket` / `switch` / `light` |
| `points[].id` | Обязателен, уникален в проекте; на него ссылаются `cables` |
| `points[].room`, `wall`, `offset` | Привязка к стене (`wall` — `id` стены); `offset` — до **середины** символа |
| `points[].ceiling` | `[x, y]` от `origin` комнаты — только для `light` |
| `points[].height` | Высота от пола, мм; обязательна для точек на стене, 0–3000 |
| `points[].count` | Постов в блоке, 1–6 |
| `points[].group`, `note` | Группа, примечание |
| `board` | Щит: `room`, `wall`, `offset` (середина), `height`, `width` = 300, `name` = «ЩР» |
| `cables[].id` | Обязателен, уникален в проекте: `cable_1` |
| `cables[].from`, `to` | `board` или `id` точки |
| `cables[].route` | `wall` / `floor` / `ceiling` — где идёт кабель; рисуется всегда под 90° |
| `cables[].cable` | Марка или сечение для подписи, например `3x2.5` |

## Вопросы и отчёт: intake.yaml, answers.yaml

`intake.yaml` описывает, что разобрано, что известно об этапах и что осталось выяснить:

```yaml
sources:
  - { file: "source/plan.pdf", note: "лист 08, масштаб по привязкам" }
stages:
  plumbing: { status: absent, note: "на листах нет сантехники" }   # «данных нет, делать не буду»
questions:
  - id: q1
    stage: plan
    target: rooms.storage.walls.w2.length          # поле модели, путь по id
    also: [rooms.storage.walls.w4.length]          # тот же ответ — в другие поля
    text: "Ширина кладовки не подписана: 1783 — расчёт 7245 − 5462"
    answer: value                                  # value | choice | text
    unit: mm
    assumption: 1783                               # что сейчас стоит в модели
  - id: q2
    stage: plan
    text: "Есть ли обмерный план?"
    answer: text
    severity: major                                # только у вопросов без target
```

**Вес вопроса.** У вопроса с `target` вес считает код по полю:

| Поле | Вес |
| --- | --- |
| Геометрия: `length`, `turn`, `origin`, `start_angle` | `critical`, если значения нет; иначе `major` |
| Привязка: `offset`, `width`, `wall`, `ceiling` | `major` |
| Остальное: высоты, толщины, подоконники, петли, группы | `minor` |

У общих вопросов без `target` вес указывает анализатор в поле `severity`.

**Статус этапа.**

| Статус | Когда | Строится |
| --- | --- | --- |
| готово | Открытых вопросов нет | да |
| есть вопросы | Есть `major` или `minor`, сумма весов не больше 12 | да, по допущениям |
| мало данных | Есть `critical` или сумма весов (`major` = 3, `minor` = 1) больше 12 | нет |
| ошибки | Ошибки в YAML этапа | нет |
| заблокирован | Не строится план, от которого зависит этап | нет |
| данных нет | Нет файла этапа или в `stages` указано `absent` | нет |

Ошибки в электрике не мешают собрать план.

`answers.yaml` хранит ответы. При загрузке они накладываются на YAML этапа, а исходные
файлы с комментариями не меняются:

```yaml
answers:
  q1: 1800                      # value / choice — подставляется в target и also
  q2: { text: "обмера нет" }    # текст — ждёт разбора анализатором
  q3: { accept: true }          # оставить допущение
```

`build` всегда пишет `out/report.md` (для человека) и `out/report.json` (для сервиса). В отчёте:
статусы этапов, открытые вопросы по весу, закрытые вопросы, ошибки и предупреждения.
Если план построить нельзя, DXF не создаётся, а код выхода — 1.

## Валидация

Выполняется перед любой отрисовкой. Сообщения на русском, с путём к полю:

```
[ошибка] room.yaml: rooms[0].walls: контур «Кухня» не замыкается: невязка ΔX = -100 мм, ΔY = +0 мм
  (всего 100 мм, допуск 10 мм). Замкнётся, если исправить одну из стен — стена w2: 4000 → 4100 мм;
  стена w4: 4100 → 4000 мм. … Размеры не подгоняются автоматически — уточните, какой размер неверный.
[ошибка] room.yaml: rooms[0].openings[1]: окно выходит за стену w3: offset 2000 + width 1400 = 3400 мм,
  а длина стены 3200 мм (лишние 200 мм)
```

Что проверяется:
- **Контур:**
  - замыкание с допуском 10 мм — до 10 мм это предупреждение, больше — ошибка с вариантами исправления;
  - сумма углов;
  - самопересечения.
- **Проёмы:** не выходят за стену, не перекрываются, ссылаются на существующую стену.
- **Электрика:**
  - комната и стена существуют, `offset` в пределах длины стены;
  - потолочная точка внутри контура;
  - высоты 0–3000;
  - щит помещается на стене;
  - ссылки в трассах разрешаются;
  - точка в проёме — предупреждение.
- **Схема:** неизвестные поля (опечатки), типы и диапазоны.

## Чертёж

| Слой | Содержимое | Цвет |
| --- | --- | --- |
| A-WALL | Стены, штриховка ANSI31 у несущих | 7 |
| A-DOOR | Двери с дугой открывания | 3 |
| A-WIND | Окна, подписи подоконника | 4 |
| A-DIMS | Размеры (`add_aligned_dim`, стиль `PLAN_1_50`, текст 2,5 мм на листе) | 2 |
| A-TEXT | Названия, площади (м²), заголовок | 7 |
| E-SOCKET | Розетки (блок `E_SOCKET`) | 1 |
| E-SWITCH | Выключатели (блок `E_SWITCH`) | 5 |
| E-LIGHT | Светильники (блок `E_LIGHT`) | 6 |
| E-CABLE | Трассы, пунктир `E_CABLE_DASH` | 1 |
| E-BOARD | Щит (блок `E_BOARD`) | 1 |
| E-TEXT | Группы, высоты, сечения, легенда | 1 |

- **Размеры** — по внутренней грани:
  - цепочка проёмов и общая длина выносятся за габарит здания;
  - у стен, за которыми соседняя комната, размеры ставятся внутри;
  - общая перегородка образмеривается один раз, со стороны большей комнаты.
- **Символы электрики** — блоки (INSERT) с геометрией на слое 0 цвета BYBLOCK: цвет берётся
  от слоя вставки. Символ на стене развёрнут в помещение.
- **Превью** затемняет светлые цвета (жёлтый, голубой, зелёный, пурпурный), чтобы они читались
  на белом фоне. В DXF цвета без изменений.

## Работа через Claude Code

Откройте репозиторий в Claude Code. Правила работы описаны в [CLAUDE.md](CLAUDE.md).

| Команда | Что делает |
| --- | --- |
| `/plan <фото или текст> [имя]` | Создаёт `projects/<имя>/` и черновик `room.yaml`, показывает таблицу «стена → длина → источник» и вопросы по `unknowns`. **Ждёт подтверждения**, затем `check` → `build` → сам смотрит лист плана |
| `/electrical <проект> <описание>` | Дописывает `electrical.yaml`, показывает таблицу точек, после подтверждения собирает проект и проверяет лист электрики |
| `/check <проект>` | Валидация и превью без перегенерации; ничего не исправляет |

Типичный сценарий:

```
/plan ~/Downloads/kitchen.jpg kv42
  → таблица размеров и вопросы «на фото нет толщины стены w3 — какая?»
  → ответ и подтверждение → project.dxf и .epd, проверка листов через render-artifact
/electrical kv42 на верхней стене кухни двойная розетка в 500 мм на высоте 300, группа QF1 …
/check kv42
```

Принципы: размеры берутся **только с фото или из текста**, без оценки на глаз; при невязке
числа не подгоняются — Claude показывает ΔX/ΔY и спрашивает; все допущения перечисляются явно.

## Ограничения

- Рисунки от руки (эскиз, план на бумаге или поверх фото) не разбираются: по ним не пишется
  модель, в `intake.yaml` — вопрос «пришлите чертёж (PDF, DWG) или обмерный план».
  Разбираются векторный PDF, скан и фото чертежа, фото помещения с написанными размерами, текст.
- Трассы схематичные: ортогональные или прямые между точками, обход стен и дверей не ищется.
- Символы УГО упрощённые. Количество постов и клавиш показывается подписью «2×».
- Наружные размеры по осям или внешним граням не ставятся — только внутренние.
- Стены по дуге не поддерживаются.
