# Shtroba admin

Админка платформы для владельца (суперпользователя): студии, люди, проекты, участники,
приглашения, коды доступа, доступ поддержки, журнал. Решение 2026-11-03 — `docs/database.md`,
«Админка платформы». Отдельный проект, как `web/`: React 19 + TypeScript + Vite, своя сборка.

```bash
npm install
npm run dev      # http://127.0.0.1:5174/admin/ ; API — floorplan-engine view (8000), другой адрес: API_URL=… npm run dev
npm run check    # типы
npm test         # vitest: логика (*.test.ts) в Node, компоненты и страницы (*.test.tsx) в jsdom
npm run coverage # то же с покрытием src/, отчёт — coverage/
npm run build    # dist/ с base /admin/
```

Вход — в просмотре (`web/`): cookie сессии общая, потому что админка живёт на том же домене по
пути `/admin/` (на сервере её отдаёт Caddy, `deploy/Caddyfile`; локально cookie на 127.0.0.1
общая для всех портов). Не вошли или не суперпользователь — экран с объяснением; API
`/api/admin/*` и так отвечает 401 или 403.

## Устройство

Вариант B макета: разделы | список | карточка; сводка, журнал и отзывы — на всю ширину. У каждой
записи свой адрес в hash (`#/projects/<id>`, `#/events?project=<id>`), ссылки на человека,
студию и проект переключают раздел.

## Таблицы и кнопки: ничего не прыгает

- Таблица — `table-layout: fixed` (`src/shared/global.scss`), ширины — `<Cols w={[null, W.day, W.act]} />`
  первым ребёнком `<table>`: число — пиксели (`W` — обычные столбцы: даты, роль, статус, число,
  действия), `null` делит остаток. Ширины не зависят от содержимого.
- Ячейка в одну строку, длинное — с «…», полный текст — в `title`; цифры — `tabular-nums`; строка
  одной высоты с кнопкой и без.
- Действия строки — `IconButton`/`Confirm`/`CopyButton` в последнем столбце `W.act` (`td` с
  `css.actions`), справа; в шапке раздела — `Button` с иконкой.
- Подсказка и вопрос подтверждения — поверх страницы (`position: fixed`), копирование меняет
  только иконку: размер кнопки и столбца не меняется. Место полосы прокрутки зарезервировано
  (`scrollbar-gutter: stable`).
- Сторонний ui-kit не берём (решение 2026-11-23): темы и вид — как у просмотра, его `ui/` и есть
  наш набор; новый компонент — по образцу оттуда.

Нарушение правила доступа (одно пространство, один проект у клиента, у студии остаётся
владелец) API возвращает 409 с причиной — она показывается рядом с действием. Код доступа и
ссылка-приглашение показываются один раз: API их больше не отдаёт.

## Тесты

Как у `web/` (`web/README.md`, «Тесты»): два проекта vitest в `vite.config.ts` — `logic` в Node и
`dom` в jsdom с Testing Library; тест — рядом с файлом (`pages/Users.test.tsx`). Подготовка —
`src/shared/testSetup.ts` (матчеры `jest-dom`, чистый DOM, адрес `#` и заглушки после теста).
API в тесте — `stubApi` из `src/shared/testApi.ts`: `fetch` отвечает по таблице
`"METHOD /путь"` → ответ (с запросом и без него), `fail(409, "причина")` — отказ с причиной,
функция получает тело запроса; запрос без ответа роняет тест, а список отправленного
проверяют после клика. Записи для ответов — фабрики `src/shared/testData.ts` (переопределяй
только нужные поля).
